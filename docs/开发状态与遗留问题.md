## 2. 本轮修掉的真 bug（都值得写进设计文档）

### 2.1 「捕鼠笼」地形 —— 掉进去就出不来（致命）

玩家高 28px（占 2 格）。生成器原来允许"地上方只有 2 行净空"的地形
（平台离地 3 格时，平台下面只剩 2 行）→ 玩家掉进去后：
* 站着占满 2 行，**跳不起来**；
* 前方一格台阶比头高，**走不出去**。

无头机器人实测：走进这种凹槽后 900 帧零位移，6/6 局卡死。

**修复（三层防御）**：
1. `gen/room.gd`：浮空平台离地高度 **≥ 4 格**（原来 3~6 格），跳台梯每级 **4 格**（原来 3 格）。
2. 生成后**填实净空不足的柱子**（`Room.build` 的"净空修复"）：空行 < 3 就填成实心。
3. **新硬约束 R6**：任何可站立格上方必须有 **≥ 2 行净空**。
   推导：站立格 `y` 的脚底在 `(y+1)*16`，身高 28 ⇒ 头占 `y-1` 行；跳一格台阶（+16px）
   头到 `y-2` 行 ⇒ 至少 2 行。

### 2.2 「单向陷阱区」—— 走得进去、通不了关（致命，已治本）

生成层的可达性只用 `A = walk ⊗ K` 的**前向闭包**；它只保证"从出生点能走到"，
**不保证"进去之后还能出去"**。本作有"跳下去容易、爬上来难"，于是存在一类格子：
* 在出生点的前向闭包里（进得去）；
* 但从它出发到不了终点（出不去）。

实测事故（seed 10919）：上层长廊正下方的凹槽，头顶被长廊堵死、前面一格台阶
比头还高 → 机器人从此再也动不了（`pn0`，规划无路）。

**修复：陷阱剪除 `GM.prune_traps()`**
```
F = 从出生格走得到的全部站立格（有向）
B = 能走到终点的全部站立格（把步长取反做 BFS：VM.reach_back_from）
F \ B = 陷阱 → 填实
```
* 计算时**把所有门当作已开**（否则门后整段会被误判成陷阱）。
* 填实是安全的：陷阱格里不可能有"出生点→终点路径"的中间节点（否则它自己就能到终点）。
* 保护格（出生/终点/钥匙/开关/门列）永不填。
* 掩码必须用**运行时的碰撞判据**（任意阻挡格），不能用运动核里的"墙"判据
  （那个只把"上下都实心"算墙，会把天花板放过去）→ `reach_from/reach_back_from`
  新增 `strict_mask` 参数，`prune_traps` 用 `strict_mask = true`。
* 代价：每层生成从 ~330ms 增到 ~460ms（一局 3 层 ~3.1s）。值得。

### 2.3 运行时：动作表缺 `dash` / `heal`（GUI 每帧刷错误）

`project.godot` 的 `[input]` 少了 `dash` 和 `heal`，而 `main.gd::_collect_input()`
每帧都 query 它们 → Godot 对每次查询都打一条 ERROR（控制台刷屏 + 拖帧）。
修复：`main.gd::_ensure_actions()` 在 `_ready()` 里兜底注册（缺什么补什么）。

### 2.4 `render/art.gd` 类型推断错误（GUI 完全起不来）

`var pos := a.p` 无法推断类型 → 整个 `main.gd` 编译失败 → 游戏根本无法启动。
修复：`var pos: Vector2 = a.p`。

### 2.5 机器人（探测工具）自身的坑（写下来避免重复踩）

* 近战判定只看水平距离 ⇒ 站在上层平台的敌人"水平距离 0"，机器人对着空气砍 700 帧。
  修复：加垂直判据 `|Δy| < 34`，并加"敌人在头顶就跳上去"的分支。
* 只按 `pl.cell()`（身体中心格）判断跳跃，而站立格用的是脚下格 ⇒ 差一格，
  该跳的地方不跳。修复：一律用 `pl.foot_row()`。
* 门锁着时只会往前撞。修复：**用真实运动核 K 当步长做路线规划**
  （钥匙 → 拉杆 → 出口），步长的轨迹掩码与物理同源 ⇒ "规划得出"≈"物理走得到"。
  这是"看得懂地图的玩家"的替身；规划失败时退到宽松判据（只要求有地板）重试。

## 3. 遗留问题（按优先级）

1. **美术替换缝**：`render/art.gd` 一个文件全包，换成贴图时只改 `draw_*` 系列。
2. **平衡**：实测中位 TTK ≈ 3.2 秒，契约上限 3.0 秒（略慢）；BOSS 血量已按
   "25~35 秒可打完"压过一档（`level._spawn_boss` 里乘 0.35），仍待手感回归。
3. **变异树**只做了"开局一次性加成 + 击杀回血"；"肉鸽获取升级"目前是
   每局结算给 cell、跨局换属性（`run_state.Meta`），局内升级（进房间选词条）还没做。
4. **合成只在背包里同类型两件之间**（按 F）；没有专门的合成界面/配方表。
5. **无头机器人**仍是启发式：它的规划图与运行时的滑动/贴边行为不完全等价，
   偶发"进得去、模型算出不来"的局部死锁（已用路点跳过 + 撞墙换边兜底）。
   几何正确性由生成层证明（见 §5.5），机器人只当**节奏指标**用。

## 4. 文档 vs 代码的已知差异（要向读者交代）

1. 地图方案 §6.3 写"下跳可达 230px"，代码实测 **273px**（文档是修前的数）。
2. 机制拆解 §4.2 注释写 0.70s，代码是 **0.65s**（代码更保守）。
3. 文档说"定点整数物理"，实际是**生成用整数定点（跨机器逐位一致），
   运行时用浮点（同一二进制一致）** —— 理由：运动核 K 由运行时物理解析式编译，
   两边必须同一套模型，否则"核里能走"和"实际能走"会漂移。
4. 无头模拟器的平衡报告打印 `伤害成长 ×(1+0.030)^(层-1)`，
   而 `DIFFICULTY.dmg_per_floor = 0.06` —— 打印口径与常量不一致，待统一。
5. 运动核掩码的"墙"判据（只算上下都实心）与运行时（任何阻挡格）**仍然不同**，
   但已通过"支撑格排除"把两者拉齐到同一套可达集合（见 §5.1）。

## 5. 第二轮：把"能玩"变成"真的能玩"（本轮新增）

### 6.1 运动核掩码的"支撑格"修正 —— 模型第一次和运行时对齐

现象：用**严格**判据（任何实心格都挡人，= 运行时碰撞）算可达集合时，
连**终点**都不在出生点的可达集合里（18/18 层全灭）。定位器 `tools/probe11.gd`
把被拒的走法连同"挡住它的格子"打出来，结论非常干脆：

* 最多次数的首挡相对格是 **(0, +1)** —— 就是**玩家自己脚下的地面**；
* 原因：轨迹掩码按 `(行,列)` 直线插值，一个"边跳边落"的长步在 `t≈0` 就把脚底
  插进了起点脚下的地面格。

**修复**（`gen/motion_kernel.gd::_build_mask`）：把起点正下方、终点正下方这两个
**支撑格**从掩码里排除（`(0,1)` 与 `(off.x, off.y+1)`）。排除后严格判据立刻自洽：
`tools/probe10.gd` 检查 18 层 → **0 问题**（终点/钥匙/开关严格可达）。
**追加约束（同一天发现，很重要）**：起点脚下那格**只在有横向分量时**才排除。
纯竖直下落（`off.x == 0`）意味着"身体根本没离开自己那一列" —— 那是想**穿过脚下的
地板掉下去**，必须照旧判非法。漏掉这个条件时，规划器会以为"站在平台上可以直接往下钻"，
于是机器人站在平台上、目标就在下方两三格，却 900 帧原地不动 —— 这是无头模拟里
最主要的卡死形态（现场特征：`tgt` 与玩家同列，而目标正好在脚下）。
注意排除的**只是这两个支撑格**：中途撞上的实心格（比如跳太高顶到天花板）照算，
那本来就不该允许。

### 6.2 半开区间：`collides()` 少了一个 eps（GUI 里玩家"悬浮+全速跑不动"的真相）

`collides()` 原来写 `x1 = floor((p.x + hw) / TILE)`。身体右缘**正好**落在格边界上时
会被判成"压在右格上"；若右格是实心，角色就**永久嵌进地形**：
两个方向都推不动（无头模拟里表现为 `vx=-240` 全速跑、三个采样点 `x` 一模一样），
向下的吸附还会把它往上顶 16px 并置 `on_ground=true` —— 历史上多次"站在半空里"、
"离地 4px 却不落地"的现场都是这一个 bug。

**修复**：半开区间约定 —— 矩形**含**上/左边、**不含**下/右边，
`x1` 用 `floor((p.x + hw - 0.01) / TILE)`（`y1` 早就有这个 `-0.01`）。
改完之后机器人不再出现"卡住但速度满格"的现场。

### 6.3 陷阱剪除改成**不对称**闭包（这是治本的那一刀）

`prune_traps` 的判据：**入口用宽松掩码、出口用严格掩码**。
* 宽松（只把"上下都实心"算墙）会**高估**玩家能到达的地方 —— 正好覆盖运行时靠
  贴边滑行、踩平台边角溜进去的那些格；
* 严格（任何实心格都挡人）会**低估**玩家能离开的地方。

于是 `宽松可达 \ 严格可离开` = **进得去、出不来**的真正陷阱区（含模型看不见的入口）。
两次都用宽松（最早的写法）会漏掉整整一类陷阱 —— 无头机器人掉进去就是 900 帧零位移。

### 6.4 S6 的定义改了（原来在测机器人，不是在测游戏）

原来 `state != won && state != dead` 一律算"卡死"，于是"跑得慢、帧上限用尽"
和"走进死胡同"混在一起。现在分开：
* `stalled`：连续 900 帧零位移（真·死胡同）；
* `timeout`：帧上限用尽但一直在推进。

S6 = `stalled ≤ 25%` **且** 平均推进 ≥ 5 个房间。理由：关卡几何的连通性由
生成层**穷尽证明**（§5.5），机器人只负责给节奏指标（帧数/击杀/TTK/承伤）。

### 6.5 关卡几何的可玩性保证（可穷尽、可复现）

每层生成时都会：把门全开 → 算 `宽松F`、`严格B` → 填掉 `F \ B`（陷阱区）
→ 校验 `spawn / goal / key / switch` 都同时落在 `F` 与 `B` 里。
`tools/probe10.gd` 是可复跑的证据（`--strict=1` 时 18/18 层零问题）。
陷阱剪除的正确性：陷阱格不可能是任何"出生点→终点"路径的中间节点，
所以填掉它不可能断开通路；填实是单调的（只会缩小可达集），也不会造出新陷阱。

### 6.7 机器人（QA 工具）本轮踩的坑，写下来别再踩

1. 规划必须用**和运动核同一套**掩码判据；用"任何实心格都挡人"时，
   采样轨迹会撞上脚下的地板 ⇒ **一步都走不出来**，`pn0` 刷屏。
2. 停滞检测必须用**格子**，不能用浮点坐标：在"地面与天花板只差 4px"的地方
   机器人会原地弹跳（数值一直在变），浮点判据永远判不出停滞。
3. 跟路点要能**跳过**够不着的路点（连续 45 帧格不变 ⇒ `path.pop_front()`），
   否则它会在一个够不着的路点下面原地跳一辈子。
4. 兜底推进要**撞墙换边**（原来"规划失败 + 前方是墙"= 顶着墙跑到天亮）。
5. 还需要一个**挣扎（unstick）**：卡住 240 帧就左右交替 + 周期起跳地乱试 210 帧，
   像真人卡住会蹦两下。加上它之后 6 局模拟从"真·卡死 3/6"变成 **0/6**，
   平均推进 7.2 → 更高、平均击杀 27、第 1 层 6/6 通过、第 2 层 5/6 通过。
   —— 说明之前那部分"关卡走不通"的结论是**机器人不会脱困**，不是关卡坏了。

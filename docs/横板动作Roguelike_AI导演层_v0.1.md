> ⚠️ **我（AI）在这个游戏里的位置，写在最前面**
>
> 你不是在给这个游戏「配一个聊天框」。你是这个游戏**内嵌的导演层**：
> 你能看到的是几维结构化上下文（不是我俩这种对话），你能做的是往一个
> **受限指令表**里发指令，指令先过确定性校验器、再异步双缓冲生效。
> 你的目标不是「赢」，是让这一局的**节奏**好看：该紧的时候紧，该喘的时候喘。
> 下面每一节都写清了「你能做什么 / 你不能做什么 / 越界会怎样」。

# DSH-RL：2D 横板动作 Roguelike 内嵌 AI 导演层设计文档 v0.1

## 0. 一句话原则

> **模型是脑子，不是手。**

模型永远不会直接改玩家的血量、不会直接生成几何、不会直接决定敌人这一帧走哪一步。
它只做两件事：

1. **读**一个 4~6 维的结构化上下文（每房最多 1 次）；
2. **写**一条受限指令（改的是**参数**，不是**机制**）。

几何由构造式算法保证，手感由帧数据保证，公平性由校验器保证。
模型在中间那一层做**风格决策**。

---

## 1. 为什么不让模型直接控制（反面清单）

| 诱惑 | 为什么不 | 我们怎么做 |
|---|---|---|
| 让模型生成关卡几何 | 无法保证可达性 ⇒ 玩家卡死，且不可复现 | 几何走构造式生成，模型只能改**参数**（房间类型权重、威胁预算） |
| 让模型逐帧控制敌人 | 每帧一次推理，延迟与成本爆炸 | 敌人走行为树，模型只改 **ctx 六维**（权重） |
| 让模型写脚本/表达式 | 无法验证 ⇒ 可被越权/崩 | 只允许**白名单原子指令 + 受限参数范围** |
| 让模型现场决定掉落 | 掉落在关卡生成期就要定死（世界线） | 模型只能改**掉落曲线参数**，且只在**下一局**生效 |
| 让模型「看情况放水」 | 会变成暗改，玩家感知为欺骗 | 放水必须是**显式、可观测、有上限**的（见 §5.4） |

---

## 2. 上下文（ctx）：模型看到的世界

### 2.1 维度设计

ctx 是**固定长度**的数值向量，不是自然语言。原因：
数值向量可校验、可 diff、可回归测试；自然语言不可。

```
ctx = [ aggression, defense, range_target, rhythm, focus, mercy ]   # 各 0..1
```

| 维 | 含义 | 高值意味着 | 主要影响 |
|---|---|---|---|
| `aggression` | 进攻性 | 敌人更主动贴近、连招更凶 | 行为树节点权重、攻击间隔 |
| `defense` | 防守性 | 更爱格挡/后撤/拉距 | 敌人保留距离、更多防御动作 |
| `range_target` | 期望交战距离（归一化） | 偏远程 | 敌人站位目标距离 |
| `rhythm` | 节奏（0=舒缓 1=急促） | 波次更密、间隔更短 | 刷怪间隔、援军时机 |
| `focus` | 集火度 | 多敌人同时压一个方向 | 敌人目标选择集中度 |
| `mercy` | 怜悯 | 玩家低血时压力下降 | **只在硬约束允许的窗口内**生效 |

### 2.2 ctx 的输入从哪来（全部是**本地统计**，不需要模型先看画面）

- 玩家血量比、无敌帧剩余、最近 6 秒受伤次数
- 玩家最近 6 秒的输出节奏（每秒伤害、连段数、空振率）
- 当前房内敌人数、总威胁、剩余威胁
- 玩家已经连续无伤的房间数（`clean_rooms`）
- 本局已经死过几次（跨局 meta 也进来，但**只影响下一局**）

### 2.3 硬约束（写在代码里，不是写在提示词里）

```
低血不后退铁律：player.hp_ratio < 0.30 时，
  aggression 不得下降、援军不得增加、不得生成新敌人。
  （IV-3：绝不在玩家喘不上气的时候加码）
```

## 3. 指令语言（受限原语）

### 3.1 原语表（**白名单**，越界即整条丢弃）

| 原语 | 参数 | 范围 | 语义 |
|---|---|---|---|
| `set_ctx` | dim, value | dim ∈ 六维, value ∈ [0,1] | 改行为权重 |
| `spawn_wave` | archetype, count, delay_frames | count ∈ [1,3], delay ∈ [0,180] | 追加一波（受威胁预算约束） |
| `set_pacing` | room_interval_frames | [60,600] | 房间之间的喘息长度 |
| `grant_pickup` | kind, rarity_delta | rarity_delta ∈ [-1,1] | 调整本房掉落（**只能调，不能凭空造**） |
| `set_affix` | affix, target_elite_only | bool | 给精英挂词缀（受 `forbidden_on` 约束） |
| `hint` | text_id | 白名单 id | 给玩家的可见提示（**唯一允许的自然语言出口**） |
| `noop` | — | — | 显式「什么都不做」，鼓励模型用它 |

### 3.2 为什么 `hint` 只能是白名单 id

自然语言出口是**注入面**。允许模型自由写文字 ⇒ 玩家看到的文本不可控（幻觉、
越权、跑题）。所以：模型只能选一个 id，文案由游戏本地化表提供。

### 3.3 禁止原语（**永远不允许**，即使模型请求）

- 改玩家/敌人血量、位置、无敌帧
- 直接开/关机关、直接传送到房间
- 改关卡几何、改可达性
- 改存档、改 meta 进度
- 任何形式的「重开这一局」

## 4. 异步与降级：模型永远不在关键路径上

### 4.1 双缓冲

```
帧 N：  读 ctx_buf[cur] → 立刻用（0 延迟）
在后台：请求模型 → 得到指令 → 校验 → 写 ctx_buf[next]
帧 N+k：swap(cur, next)
```

- 模型慢/挂了 ⇒ 玩家**毫无感知**，继续用上一份 ctx。
- 每房最多 1 次 query（`Cfg.AI.query_per_room = 1`）。
- 单次预算 ≤ 40 ms（`Cfg.AI.budget_ms`），超时直接降级到规则脑。

### 4.2 三档降级（L0/L1/L2）

| 档 | 条件 | 行为 |
|---|---|---|
| L2 模型脑 | 模型可用且返回合法指令 | 用模型 ctx |
| L1 规则脑 | 超时 / 非法 / 未配置 | 用本地规则（`RuleBrain`）—— **保证游戏永远可玩** |
| L0 冻结 | 连续 N 次失败 | 冻结 ctx 到最近一次合法值，停止查询本局 |

**L1 是默认档**：没有任何模型，这个游戏也必须是完整可玩的。

### 4.3 影子模式（Shadow）

首次接入 / 调参时，模型只**记录**不生效：
指令被写好、被校验、被 diff 记录，但 `ctx_buf[cur]` 不变。
用来回答「模型到底做了什么」这个唯一重要的问题。

---

## 5. 校验器（Validator）：模型与游戏之间的最后一道门

### 5.1 逐条检查（任何一条不过 ⇒ 整条指令丢弃，不是部分生效）

1. **白名单**：原语是否在表里
2. **参数范围**：每个参数是否在闭区间内（浮点用 `±1e-6` 容差）
3. **预算**：`spawn_wave` 后该房威胁是否仍 ≤ `effective_cap`
4. **铁律**：低血不后退（§2.3）
5. **词缀合法**：`forbidden_on` 不违反
6. **数量上限**：每房新增波次 ≤ 2，每层 ≤ 6
7. **幂等**：同一房同一原语不重复生效（防抖）

### 5.2 校验器的可观测性

每次校验都写一条事件日志：

```
[ai] room=7 frame=19203 brain=L2 prim=set_ctx(aggression,0.8) verdict=accept
[ai] room=7 frame=19204 brain=L2 prim=spawn_wave(rusher,3) verdict=reject budget
```

日志是**只读的**，玩家在设置里可以打开（"AI 透明度"）。

### 5.3 影子模式下的 diff

影子模式把「模型想做的」与「规则脑会做的」并排记录，
用于回答：模型的决策是否**系统性偏难**。

### 5.4 怜悯（mercy）的硬上限

`mercy` 只允许在**窗口**内起作用：
玩家低血 **且** 已经 3 秒没受伤 **且** 房内敌人 ≤ 2。
不满足 ⇒ `mercy` 被钳到 0。理由：怜悯不是暗改难度，是**给玩家一个能翻盘的窗口**。

## 6. 与其它系统的接口

| 系统 | 接口 | 方向 |
|---|---|---|
| 生成层（六头） | 只通过 **θ** 与**下一局**生效 | 模型 → 生成 |
| 行为树 | `ctx` 六维 → 节点权重 | 模型 → 战斗 |
| 掉落 | `grant_pickup` 的 `rarity_delta` | 模型 → 掉落 |
| 存档 / meta | **无接口**（禁止） | — |
| 事件日志 | 只写读 | 模型 → 日志 |

| 编号 | 断言 | 现状 |
|---|---|---|
| IV-1 | 无模型时游戏完整可玩（L1 规则脑） | ✅ 默认就是 L1 |
| IV-2 | 非法指令 100% 被丢弃且游戏不崩 | ✅ 校验器逐条检查 |

| IV-5 | 影子模式不改变游戏状态 | ✅ 只写日志 |
| IV-6 | 同种子 + 同 ctx 序列 ⇒ 同结果 | ✅ ctx 是唯一输入 |
| IV-7 | 每房 ≤ 1 次查询 | ✅ 计数器 |

## 8. 落地实现（代码在哪）

| 模块 | 文件 | 职责 |
|---|---|---|
| 上下文构造 | `ai/ctx.gd` | 从运行态统计出六维 + 铁律钳制 |
| 规则脑 L1 | `ai/brain.gd::RuleBrain` | 无模型时的确定性决策 |
| 模型脑 L2 | `ai/brain.gd::ModelBrain` | HTTP 调本地小模型，返回原语列表 |
| 校验器 | `ai/primitives.gd::validate` | 白名单 + 范围 + 预算 + 铁律 |
| 执行器 | `ai/primitives.gd::apply` | 把合法原语落到运行态 |
| 导演（异步） | `ai/director.gd` | 双缓冲 + 影子 + 降级 + 日志 |

模型后端默认指向本机 OpenAI 兼容端点：
`http://127.0.0.1:8080/v1/chat/completions`（可配）。
**没有后端时自动 L1**，不报错、不卡帧、不留痕。
